# v0.1.0 final acceptance runbook

Verifies the submission state (Tag `v0.1.0`, Block 5) end-to-end on a clean host. This is the procedure that must pass before the submission PDF is uploaded to Moodle. The Block-4-era counterpart is [`beta-mvp-acceptance.md`](beta-mvp-acceptance.md) — kept for traceability of the original milestone.

## Pre-state

- `main` is checked out at Tag `v0.1.0`.
- `make build` exits 0 with warnings-as-errors enforced.
- `make test` reports **234 / 234 green** across all eight test projects (see SUBMISSION.md §3.3 table).
- The last CI run for the tag is green: `gh run list --workflow=ci.yml --branch=main --limit=1`.

**Time budget:** 30–45 min.

## Step 1 — Clean host

```bash
docker compose down -v   # remove any prior volumes
git checkout v0.1.0
```

## Step 2 — Bring the production stack up

```bash
cp .env.example .env
# Fill: Postgres password, RabbitMQ default, OIDC client id/secret,
# Skills__Wallabag__*, Skills__Vikunja__*, Ai__*.

docker compose up -d --wait
```

Acceptance:

- All containers reach `healthy` within 60 s (NfA-A1).
- The migrations init container (`flowhub.migrations`) exits 0 before `flowhub.web` is ready (NfA-O3).
- `curl -fsS http://localhost:5070/health/live` returns 200.
- `curl -fsS http://localhost:5070/metrics` returns Prometheus-format metrics including `dotnet_*` and `http_*` series (NfA-O1).

## Step 3 — Web UI smoke

1. Open `http://localhost:5070`.
2. Sign in via Authentik OIDC.
3. Submit a capture via Quick Capture: `"https://example.com/article-about-rust"`.
4. The lifecycle chip transitions `Pending → Classified → Routed` within ~5 s.
5. The matched skill appears on the dashboard recent-captures card.

## Step 4 — Telegram smoke

1. Send a text message to the configured Telegram bot.
2. The bot replies with a confirmation containing a Capture ID.
3. Refresh the dashboard: the capture appears with `ChannelKind = Telegram`.

## Step 5 — Real-integration write

1. Submit a URL that the classifier routes to Wallabag.
2. Confirm in the homelab Wallabag UI that the article is added.
3. Repeat with a todo phrase routed to Vikunja; confirm in the Vikunja project.

## Step 6 — Failure & retry

1. Stop the Vikunja container (or set an invalid token).
2. Submit a Capture that should route to Vikunja → it lands in `Stage = Failed`.
3. Click **Retry** on the Capture-detail page → a new `SkillRun` is appended.
4. Restore Vikunja, retry once more → lifecycle resolves to `Routed`.

## Step 7 — Semantic search

1. Seed ≥ 20 Captures (or wait for them to accrue).
2. Embeddings populate `Captures.Embedding` (`vector(1024)`) within seconds of classification.
3. `GET /api/v1/captures/search?q=…&mode=semantic` returns the top matches by cosine distance, p95 ≤ 200 ms (NfA-S1 envelope).

## Demo overlay smoke (optional)

docker compose -f docker-compose.yml -f demo/docker-compose.yml up -d --wait

Then visit `https://demo.flowhub.freaxnx01.ch` (or `http://localhost` if running locally) and confirm:

- A new Capture is classified by OpenRouter (or falls through to `KeywordClassifier`).
- After 15 min, the fixture set is restored and any user captures are gone.
